# Development Workflow

This document defines the 9-step process for every feature implementation.

---

## 1. Clarify

When a request is made, ask clarifying questions to understand:
- What exactly should be built
- Edge cases and constraints
- User experience expectations
- Integration requirements

---

## 2. Plan

Create a detailed implementation plan covering:
- **Efficient technical architecture** — Choose the simplest solution that meets requirements
- **Bug/error risk minimization** — Identify potential failure points upfront
- **High-craft visual implementation** — Prioritize polish and user experience

---

## 3. Execute

Build the feature according to the plan:
- Write clean, maintainable code
- Follow existing patterns in the codebase
- Test incrementally during development

---

## 4. Review

Perform systematic testing and optimization:
- Test all functionality paths
- Verify edge cases work correctly
- Optimize for cleanliness, efficiency, and performance
- Update `benchmarks.md` if performance metrics change

---

## 5. Present

Show changes to the user:
- Demonstrate new functionality
- Explain key decisions made
- Ask for feedback

---

## 6. Iterate

Implement feedback if needed:
- Address any issues raised
- Refine based on user input
- Re-test affected functionality

---

## 7. Document

Update project documentation:
- Add entry to `plan.md` under Shipped Features
- Add detailed entry to `history.md` with design decisions

---

## 8. Reflect

If problems occurred during development:
- Capture in `feedback.md`
- Document root cause
- Note prevention strategy for future

---

## 9. Commit

Finalize the work:
- Commit with descriptive message
- Push to GitHub
